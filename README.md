## ✨ v2.19.0（2026-09-11）——表驱动结构性根治：新增同步字段从「改 5 处」到「改 1 处」

- 🏗️ **状态字段注册表 STATE_SCHEMA（唯一事实源）**：新增一个云同步字段，此前要改 5 处（state 默认值 / loadData / saveData 手写清单 / CLOUD_SYNC_FIELDS 白名单 / smartMergeData 合并分支），漏一处就出「删除后复活 / 字段不传播 / 默认值缺失崩溃」（v2.18.3 处分、v2.18.12 荣誉、v2.18.14 导入、v2.18.15 学生接连踩的都是它）。现改为一张表驱动全部链路：默认值由 buildDefaultState() 遍历生成、云端白名单按 cfs=1 派生、saveData 落盘清单按遍历生成、合并按 ms 分发到 MERGE_ST 策略引擎、JSON 备份导入的墓碑集合按 tomb=1 派生——**加字段只改 schema 一处**
- 🧩 **合并逻辑逐字搬运、语义不变**：25 个策略函数 = 旧 smartMergeData 内联分支原样迁移（墓碑仲裁 / 三方并集 / 时间戳取大 / 办结优先 / 本地优先等全部保留）。42 套旧回归全绿 + 新增 _v21200 套件 14 项元护栏（含「CFS 派生必须与 v2.18.15 手写白名单逐键一致」的漂移断言）

## ✨ v2.18.15（2026-09-11）——修复「删除的学生过会儿又回来了」

- 🪦 **学生名单接入删除墓碑（studentDeleted）**：此前学生合并是「按 id 并集、保留较新」但没有删除记录——云端旧副本、其他未刷新设备、旧 JSON 备份里的该学生，每次拉取合并都会把已删学生**并回来复活**（与 v2.18.12 荣誉、v2.17.30 原因目录同类根因）。现单个删除与**名单同步移除**都登记删除时间戳并随云同步传播：合并时按墓碑剔除、双向防御、旧备份混入的已删学生由加载自愈过滤
- 🛡️ 墓碑跨设备取大合并，任何一端删除全局生效；重加学生会用全新 id，不受旧墓碑影响

## ✨ v2.18.14（2026-09-11）——修复「导入 JSON 备份后荣誉复活 / 部分数据丢失」

- 🪦 **荣誉复活第三条路堵死**：JSON 备份导入此前按 15 个字段的**白名单重建**数据——备份里的旧荣誉（含已删的示例荣誉）被原样恢复，本机的**删除墓碑（honorDeleted）被擦掉**，同时 honors/leaves/exams/todos/workLogs/notices/creditBank/customDorms 等全部新字段被静默丢弃，且这份残缺数据 2 秒后还会自动推上云、顶掉云端完整数据。现改为**覆盖式合并**：以本机现有数据为底，仅用备份里出现的同步字段覆盖其上
- 🛡️ **删除墓碑不可被旧备份回滚**：`honorDeleted`/`catDeletedAt`/`catRevived` 与本机取大合并、`catDeleted` 并集——旧备份既不能复活已删荣誉，也不能抹掉删除记录
- 🧩 纯函数 `mergeImportData` 可独立测试（新增 `_v2198_test.js` 11 项，含 ★复活场景端到端复现）

## 📖 使用方法

### 本地使用
1. 直接双击 `index.html` 打开
2. 所有数据存储在 localStorage
3. 在设置页导出/导入数据进行备份

### GitHub Pages 在线版
1. 推送 main 即自动部署（GitHub Pages）
2. 访问 https://cheeeom.github.io/class-manager/
3. 按下节配置 GitHub Token 开启云同步
4. 之后每次修改数据 2 秒后自动推送到仓库 `data.json`
5. 其他设备打开网页（或切回前台）自动拉取合并

### ☁️ 云同步配置（v2.6.1 起必须）
1. GitHub → Settings → Developer settings → **Fine-grained tokens** → Generate new token
2. Repository access 选「Only select repositories」→ 勾选 `cheeeom/class-manager`
3. Permissions → Repository permissions → Contents → **Read and write**
4. 打开工作台 → 设置 → ☁️ Git 云同步 → 「配置 GitHub Token」→ 粘贴保存（会自动验证）
5. 每台需要同步的设备都配置一次；token 只存在各设备本地，不进入代码

### 数据同步流程
```
设备A修改 → 2秒后自动推送 data.json 到仓库 → 设备B打开/切回页面 → 自动拉取智能合并
```

### PWA 安装（移动端）
1. 访问网站
2. Safari：「分享 → 添加到主屏幕」；Android/Chrome：使用安装提示
3. 可离线使用，数据在恢复联网后自动同步

## 🔧 技术栈
- 纯 HTML/CSS/JavaScript（无框架、无构建、零依赖，单文件应用）
- localStorage 本地存储 + GitHub Contents API 云同步（自动推送/智能合并）
- SHA-256 加盐哈希登录（纯 JS 实现，兼容 file:// 协议）
- Service Worker PWA 支持（导航/数据网络优先，静态资源缓存优先）
- Canvas 图片压缩（课程表/头像/通知图片）与手绘图表
- GitHub Actions 无 —— 部署即 push main，Pages 自动构建
